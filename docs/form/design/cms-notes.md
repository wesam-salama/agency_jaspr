# Form Architecture — local project editor

13 October 2026. This is a working, self-initiated local CMS demonstration. It does not establish a hosted CMS, user authentication, a client account or server publication.

The editable source is `web/assets/selected-work/form/site/editor.html`, `cms.js` and `cms.css`. It imports the same `data.js` used by the implemented public website. The three canonical study records remain in `DEFAULT_PROJECTS`; published changes occupy `form-projects-v1` in the current browser. Drafts use a separate `form-editor-draft-v1` key, and the implemented public preview explicitly reads `form-editor-preview-v1` from session storage when `preview=1` is present. A draft never replaces the published record before Publish changes succeeds.

Every record includes a stable ID, unique slug, bilingual title/summary/category/location/material explanation, study year, exact Studio concept status, optional area, ordered images, separate desktop/mobile focal coordinates, bilingual alt text and captions, ordered story sections and a next-project relation. The stable ID is displayed and preserved. Arabic fields shape with local IBM Plex Sans Arabic; the editor interface switches to RTL without adding Arabic tracking. Latin file paths and stable identifiers retain LTR direction.

Editors can change content, inspect two live image crops, open the full image, add an existing study asset, remove an image, select each chapter image, reorder chapters, and add/remove chapters. Removing an image preserves story text; a missing relation is visible and blocks publication until a replacement is chosen. Additions receive stable IDs. Native controls, labelled fields, visible focus, inline errors, error-summary links and a status live region support keyboard operation. Structural moves restore focus to the moved section control; native confirmation protects discard and removal actions.

The crop panel is explicitly scoped to **Project-page crops**. The opening image previews at 16:9 desktop and 4:3 mobile; other story images use 4:3 at both sizes. The labelled material detail previews its primary use at 16:7 desktop and 4:3 mobile, with a note that it can also appear in a 4:3 story chapter; the full public preview shows every use. Diagrams retain their full authored 8:5 ratio with contain fitting, and their unused focal controls are disabled while stored coordinates remain intact. The panel does not imply the different homepage hero framing. The independent review corrected the initial generic 16:10/4:5 editor ratios; the affected screenshot was recaptured and its implemented ratios are asserted in the browser flow.

Publishing validates required bilingual fields, unique addresses, concept status, local imagery paths, image captions/descriptions, focal ranges, study year, text bounds and relations. The current draft must have been previewed. Actual study images must load before publication. Unavailable browser/session storage produces an accessible explanation and keeps the in-memory draft; failed saving does not replace the existing published store. The editor never uploads images or sends messages.

`cms.test.mjs` checks retained story/image content during reordering and removal, independent numeric focal updates, long permitted titles, omitted optional area, empty galleries, duplicate slugs, misleading status, excessive text, published data round-tripping and preservation after a storage exception. Run with `node --test web/assets/selected-work/form/site/cms.test.mjs`. All six tests passed on 13 October 2026; `node --check` and the scoped diff check also passed.

The real browser flow is reproducible through `docs/form/tools/cms-browser-checks.cjs`, using bundled Playwright and local headless Chrome against the owned preview at port 8797. Its final `cms-browser-checks.json` has eleven passing checks and no page JavaScript errors: required-field blocking/first-invalid focus, latest-preview requirement, amended summary in the actual project template, publication visible in another public page, draft recovery after reload, independent live focal points, keyboard story reorder with retained image relation, missing-image relation with preserved story, Arabic RTL at 390 px with zero horizontal overflow, successful long-title/absent-area publishing, and draft preservation after a simulated storage SecurityError. The browser used an isolated context; it changed no user profile or external destination. Five implementation captures are retained under `docs/form/verification/website/cms-*.png`; each was opened and visually inspected.

## Local maintenance record

The first working editor implementation moved chapter records correctly, but the keyboard browser check revealed a malformed adjacent-attribute selector in focus restoration. The subsequent local revision corrected that selector and uses an available neighbouring move control when the moved action becomes disabled at the first/last position. The same full browser flow then passed. This is a demonstrated maintenance correction to an implemented demo, not an assertion of an ongoing commercial support contract.
